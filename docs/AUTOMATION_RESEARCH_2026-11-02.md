# 自动连接与生产效率调研（2026-11-02）

## 先纠正协作模式的含义

早期`desktop_bridge.request_chatgpt`持久保存任务ID、阶段、提示词与参考图，抛出`PendingChatGPT`暂停图；用户回传JSON/图片后校验并继续。它没有自动读取聊天窗口。早期《雨夜留灯》素材通过创作会话生成后导入，不是网站后台自动生成的证据。

v2.4接入官方`codex exec`后文字/视觉能自动返回，但图片适配器只检查自己指定的`image.png`。没有得到这个文件就推断“账号未提供生图工具”不够准确。该版本失败记录保留，不改写历史。

本轮使用官方App Server和本机0.166.0生成的协议Schema复查，确认原生`imageGeneration`事件携带`result`或`savedPath`等产物信息；本机真实生成了蓝色圆形PNG。新适配器按结构化事件导入，而不依赖模型在文字中写路径或把图片复制成指定名称。工具声明可用仍不等于实际生成通过。

## 本轮效率改进与验收

1. **官方进程复用、会话隔离**：stdio进程可复用，每次生成创建独立临时thread；不把一个项目的历史拼进另一个项目。连接断开不自动重放可能已收费的调用。
2. **逐格断点**：每完成一格就提交任务进度。恢复时匹配提示词、当前模型连接、参考图内容与顺序，且确认图片可读后才复用。
3. **按证据复用审核**：只复用此前通过且提示词、提供方和所有参考图哈希未变的审核。失败项不缓存；改了人物参考或前格会重新检查相应依赖。
4. **旧待办自动转换**：配置好自动连接后，可将旧人工待办明确改为自动执行。旧待办记为superseded，不伪造已提交的JSON。
5. **首次连接可完成**：自动连接启动器包含依赖和官方登录步骤；网站内核验当前账号的文字、视觉和图片后再启用，保留原API和人工模式。

[效率回归报告](../benchmarks/AUTOMATION_EFFICIENCY.md)区分合成调用数测试与真实模型验证。没有把单次测试写成普适速度或费用收益。


## 真实流程验收结果

本机新向导的文字、视觉、真实图片验证均通过。另以原创两格猫故事运行真实生产图：两格均自动生成，视觉审核发现推门动作/场景问题，触发只重画失败格。后续一次生图超时，明确恢复一次后保留已通过格并再次复核，最终按限次规则停在人工修订，没有成稿成功标记。此案例说明自动连接、进度和质量门确实工作，同时暴露模型细节与服务耗时限制；不能宣传为“两格最终成稿已验收”。

单元测试曾继承本机自动图片模式，已终止那次测试，随后固定测试提供方、清除测试凭据并拒绝未模拟的原生模型/HTTP调用。合成测试输出不计入真实模型验证。[完整功能记录](../benchmarks/native-automation-2026-11-02.json)。
