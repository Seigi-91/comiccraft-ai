# 小说 → 可编辑改编 → 分镜与漫画

生成改编章时，流程先从原著片段提取角色卡，区分原著事实与漫画造型设定。角色卡随任务保存，并在项目页展示。大纲确认后，分镜和绘画沿用相同的人物姓名、关系和视觉设定。

## 使用步骤

1. 创建普通项目（可以只填名称），或打开已有项目。点击「小说改编 · 导入原著」。原有灵感创作入口不变；一个项目可以同时包含普通章和改编章。
2. 展开「导入新小说」，粘贴文本或上传 TXT / Markdown。填写标题，预览分段，再保存原著到项目。
3. 选择一本原著和一个片段，阅读原文。设定漫画章节标题、改编方式、分镜数、必须保留的事实、改编/前情要求。
4. 点击「创建改编章节」。这里只保存来源与设定，不调用模型。重复点击同一片段会打开已有章，不覆盖作品。
5. 点击已有「生成漫画」。默认 ChatGPT 模式复制任务到本机 ChatGPT，回填 JSON；文字 API 模式使用已配置服务。
6. **先停在改编大纲审阅处**。检查保留事实、改编调整、删减、待确认信息，以及角色、世界观和剧情。此时尚未生图。
7. 在「大纲」标签修改并保存（复用现有下游失效确认和版本历史），再点击「继续任务」。如果无需修改，可以直接继续。
8. 继续完成原有分镜、台词、生图、审核与成稿。图片连接仍可独立选择 ChatGPT / API；气泡、局部蒙版精修、批量工作台、特效和回退继续沿用。

## 三种改编方式

- **忠实原著**：要求保留关键事件因果、人物关系与结局，优先将叙述转成可见画面。
- **适度改编**：允许压缩节奏，仍需列出变化和删减。
- **自由改编**：允许重构，但必须明确列出改动，不能将新写内容伪装成原著事实。

这是给模型的约束，不是语义忠实度保证。必须人工核对原著。不确定外貌、时间或关系应列入待确认项；重要外貌/服装请同时在项目角色档案中设定、审批和添加参考图。改编要求中可提供前情摘要，不必依赖模型猜测。

## 原文与篇幅

- 单次正文最多30万字符；文件最多2MB，支持 UTF-8 / GB18030。PDF、EPUB、DOCX 暂不直接解析，先导出纯文本。
- 保存时移除开头BOM、统一换行为LF，计算此规范文本的SHA-256；除此之外不静默截断正文。
- 识别常见中文「第…章/回/节/卷/部」、序章/楔子/尾声、英文 Chapter 标题及其 Markdown 标题。长章节优先在段落边界切分，每段最多8000字符；无标题正文也会分段。切分只是本地规则，不是AI场景理解。
- 最多200个片段，超过时明确报错，请分卷导入。片段边界采用规范文本的字符偏移，所有片段可拼回完整规范文本。
- 每个片段对应一个漫画章节，设定1–24格。自动生成的分镜数须与设定一致，错误回填会被拒绝；之后手工编辑分镜仍沿用现有编辑器规则。
- 这是逐片段工作流，不是整本长篇一次性自动改编。选段可能在事件中间结束，需要审阅并在备注中补充必要前情。跨章使用原有角色资料和最近三章大纲，不宣称拥有整书长期事实库。

## 保存与回退

原著独立存入本机数据库，不改写项目灵感或旧章节。漫画章保留原著ID、标题、全文/片段SHA-256、字符范围、选段原文和创建时的改编设定。创建后设定快照不自动变化；编辑改编内容使用大纲中的方案。需要另一种改编版本时，可重新导入原文，在另一份来源记录或项目中创建章。

生成任务冻结该快照，暂停恢复、编辑后继续和章节回退均保留来源。回退恢复大纲/分镜/台词/图片等漫画状态，不修改原著。删除整个项目会一并删除其原著和改编关联，沿用项目现有删除入口。原著与改编输入保存在本机；发起生成时，选段会交给你选择的ChatGPT/文字服务，并继续用于分镜和台词。它不会自动公开到GitHub。

## 接口与兼容

前缀 `/api/novels`，精确Schema见本机 `/docs`：

| 路径 | 用途 |
|---|---|
| `POST /preview`、`POST /preview-file` | 文本/文件分段预览，无模型调用 |
| `GET/POST /projects/{project_id}` | 列出/保存项目原著 |
| `GET /projects/{project_id}/{document_id}` | 查看原著、片段和已创建章节 |
| `POST /projects/{project_id}/{document_id}/segments/{index}/adapt` | 幂等创建该片段漫画章，不生成图片 |
| `GET /chapters/{chapter_id}/source` | 查看漫画章来源快照；普通章返回null |

新增 `novel_documents` / `novel_adaptations` 两张表，启动时创建，不修改旧表列或迁移旧作品。原生成任务接口、编辑器和模型连接方式保持兼容。

## 已验证与未验证

测试覆盖无损分段、字符/文件限制、UTF-8/GB18030、项目归属、重复创建、项目删除清理、ChatGPT回填校验、API模式审阅停顿、方案编辑、继续分镜、台词、生图、成稿和回退后的来源一致性。使用确定性合成回复与测试图片；这些测试不证明真实模型的文学理解、小说忠实度或角色画质。真实长篇、多模型和人工审阅质量仍需进一步实测。


## 从参考资产到成稿

1. 在「视觉参考与分镜草图」中生成参考候选、上传参考图，或沿用已有分镜。确认后锁定为项目版本，同一小说的后续章节可以继续选用。
2. 小说生成大纲后先确认剧情。分镜与对白生成后暂停在草图阶段，可看焦点、角色站位说明、子镜头框和对白编号，修改动作、子镜头范围与对白位置。改编格数在创建章节时确定。
3. 每格可选三张锁定参考，确认草图再绘图。绘图与视觉复核读取相关参考，生成记录保存实际附图及校验值。可绘制的子镜头布局依然受图像模型遵循能力影响。
4. 对成稿可指定多格一起修订。原图与版本记录会保留，重绘只在所选范围内进行。关联证据改变的其他格会重新审核，若发现问题，停下来说明；可在版本历史恢复先前的成稿。仅改气泡时直接重新排版。
5. 同一份原著后续片段复用已完成前章的角色设定与末镜说明。项目参考图可逐格重新选择。该记忆以完成稿为依据。

角色参考先行和渐进式展示借鉴 [Story to Manga](https://github.com/victorhuangwq/story-to-manga#how-it-works)。分镜、资产和排字分离以及前章记忆借鉴 [MangaFlow 论文](https://arxiv.org/html/2605.28173v2)。这里采用现有 SQLite 与 LangGraph 实现。
