# ChatGPT自动连接：安装后本人登录，之后自动返回结果

v2.5使用官方Codex App Server连接ChatGPT账户模型，文字、视觉与图片可以自动返回网站。它是本地官方连接器调用云端模型，仍需要网络、本人账户权限与额度。**不是作者账号共享，也不需要每次复制JSON。** 原API和人工回填选项保留。

## 新下载用户

1. 下载最新版Windows安装ZIP，解压后双击 **`Install-ComicCraft-Auto.cmd`**。它安装网站依赖与固定版本官方连接器，然后打开本人ChatGPT登录流程。旧的`Install-ComicCraft.cmd`仍只安装网站。
2. 由本人完成官方登录，不能由项目代填密码或绕过账号权限。已有官方登录可能直接复用；不同用户的首次OAuth仍需本人操作。
3. 网站启动后打开「创作团队与设置」的自动连接向导；自动启动器会直接打开此页。
4. 确认使用额度，选择验证文字、视觉及可选图片，预览真实生图测试结果。
5. 通过后点击「启用已验证的自动连接」。创建项目或小说改编章并生成，结果自动回到网站；小说改编大纲仍保留审阅停顿点。

已有网站可在设置页下载独立登录助手，先解压再运行CMD；也可点击「打开官方登录流程」在浏览器中完成登录。macOS/Linux使用`bash start.sh --setup-codex`；首次安装和系统权限/代理仍需真实用户反馈，未制作签名桌面App。

原安装不自动升级或覆盖作品。升级前备份`.env`、数据库与`data/`，在新目录验证。连接器脚本只管理专用用户目录中的官方npm包，不覆盖用户的桌面应用。

## 为什么之前需要人工回填

早期模式将提示词、参考图和阶段持久保存，等待用户自己在ChatGPT生成，再回填JSON或图片。网站校验后恢复LangGraph。这是人机交接，不是后台自动操作聊天窗口。早期示例漫画的导入不能作为网站自动生成的证据。

v2.4的`codex exec`文字/视觉可用，但图片代码只等待指定文件名，导致没接到图片时归因于“未提供工具”。本轮通过官方App Server原生`imageGeneration`事件取得真实PNG，修正了这个判断和接收逻辑；保留旧失败记录供追溯。

**2026-11-02，本机0.166.0的真实向导已验证文字、附图识别和生图全部通过，并成功启用自动文字及图片连接。** 这些是连接功能测试，不是文学理解、人物一致性或画质排行榜；新用户仍须验证自己账号的能力。

## 旧人工待办如何继续

在设置中验证并启用当前阶段的自动连接后，回到项目点击 **「改用自动连接继续」**。旧待办记为`superseded`，不会伪造已提交的JSON；同一阶段交给所选自动服务执行。该操作会消耗额度，未自动替换历史已生成作品。

如果文字已自动、图片仍为人工，文字可以继续自动，但图片阶段仍会等待回填；只有明确选择并验证图片自动连接后才会自动绘画。局部精修需要另行验证，向导不会因普通生图通过就启用蒙版接口。

## 技术与失败边界

- 使用官方stdio协议：管理登录、创建独立临时thread、提交turn、消费结构化完成事件。stdio进程复用，项目/任务不共用对话历史。
- 图片只接受当前thread的原生生成事件；校验状态、失败字段、可读的真实光栅数据、目录范围和大小。忽略模型文字里自称成功或给出的任意文件路径。
- 禁用Shell、应用、插件、网页和子代理；对用户已有额外MCP逐项禁用并检查工具未暴露。无法隔离时明确失败，不带着额外工具继续执行。官方托管上层配置仍可能限制能力。
- 官方CLI自行管理登录；网站不读取/复制登录令牌，不把API密钥转发给子进程。API-key登录不会悄悄作为ChatGPT登录使用。
- 超时/断开不自动重放可能已消耗额度的调用；原HTTP/API路径与显式`CODEX_TRANSPORT=exec`文字兼容模式保留。
- 持久上限统计适配器执行次数，不等于底层推理/工具轮数或金额。记录真实数值usage，费用缺失保持未知。
- 图片尺寸、画风、原文忠实度和人物连续性需要检查。整体重绘可能改变构图；只有已有蒙版合成才保证原始分镜未选区像素保留。

默认`CODEX_TRANSPORT=app_server`，连接器固定安装`@openai/codex@0.166.0`并包含协议回归测试。该协议部分字段仍为实验性，版本升级应先测试。安装/状态检测不生成作品；真实能力验证必须由用户明确确认额度。

## 效率改进

每完成一格立即保存进度，恢复时核对提示词、连接、参考图内容与顺序，仅复用匹配的可读图片。审核只复用此前通过、且图片与所有依赖参考均未变化的记录。更换人物参考或前格会使相应审核失效，不把旧通过无限沿用。

## 真实生产图测试的限制

本机已自动生成两格漫画并触发按问题重绘，期间出现过生图超时；明确恢复一次后最终停在人工质量修订，未通过最终成稿验收。自动接收图片不等于每张图动作、空间与身份都正确。查看 [功能记录](../benchmarks/native-automation-2026-11-02.json)。单元测试固定提供方并阻止未模拟真实调用，防止测试继承操作者账号设置。

### 文件权限边界

文字使用官方 read-only 沙箱，生图使用 workspace-write 沙箱，工作目录为本次任务目录。模型侧禁用 Shell、view_image、额外 MCP 等工具，只直接附加复制到本次目录的参考图。标准沙箱不等于所有其他本机文件都不可读，不能宣称文件系统完全隔离。实验性的命名权限配置在本机固定版本与服务端组合中出现协议错误，因此本版本明确采用上述标准沙箱；不使用无限制执行。
