# 开源传播与真实用户增长计划

目标是让合适的创作者用上项目，再把真实价值转化为收藏、反馈和贡献。Star 是结果指标，无法承诺增长数量。基线：2026-11-02 GitHub 公开元数据为 2 Stars、0 Forks；后续以实时页面为准。

## 本轮已落实的转化路径

GitHub / 搜索 → 中英文 README → [无 Key 编辑体验](https://seigi-91.github.io/comiccraft-ai/demo.html) → 本机安装 → 修改并导出第一格 → 自愿 Star / 问题反馈。

首页展示真实漫画、实际编辑能力与 API/ChatGPT 边界；英文 README 面向国际开发者；Issue 表单帮助反馈而非让新人自行猜格式。交互体验是独立静态实现，不代表完整后端已经公开托管。

## 接下来四周

| 阶段 | 工作 | 交付物 | 观察指标 |
|---|---|---|---|
| 第 1 周 | 请 3–5 位真实使用者按安装说明试用，先修阻塞 | 安装问题列表、首格编辑录像、已验证平台 | 首次启动成功率、到首次导出的时间；说明样本量 |
| 第 2 周 | 做一个“气泡避开脸部”和一个“修手不改背景”的短教程 | 2 个 20–40 秒演示、原图/蒙版/对比和步骤 | 完整观看、有效反馈、成功复现人数（平台提供时） |
| 第 3 周 | 在允许展示作品和开源工具的社区发布一次有内容的介绍 | 中文/英文帖各一版，含限制和体验链接 | 引荐来源、安装反馈、自然 Stars/Forks；不盲目跨群转发 |
| 第 4 周 | 根据实际问题发小版本并回访反馈者 | 更新日志、已修问题、3 个清晰贡献任务 | 问题关闭质量、复用/贡献者、第二次使用意愿 |

渠道可考虑 GitHub 项目介绍、相关开发者社区、漫画创作社区和技术视频平台；每次发布前阅读当地规则、确认自我推广是否被允许。先贡献具体教程，再介绍项目。不在无关 Issue/PR 下发广告，不冒充独立推荐者。当前这些是待人工执行的建议，不代表已经发布。

## 维护者每周手动记录

- GitHub Stars/Forks：公开数量，可低成本复查。
- Views / Clones / Referrers：仅维护者可见且有时间窗；访问仓库 Insights → Traffic，记录覆盖日期，不推断实际活跃创作者人数。
- 安装成功/失败、系统与首个导出时间：自愿反馈，不加入隐蔽追踪。
- 贡献者数、首次响应时间、可复现问题与解决情况。
- 按渠道观察一段完整周期；不要从一两次 Star 变化判断营销成败。

仓库不会为了推广默认上传创作内容、收集密钥或加入访客追踪。若将来增加遥测，应另行说明、最小化并获得用户选择。

## 推荐主张与素材

主张：**从第一稿到可修改的成稿：你控制台词、气泡和局部修复，模型负责提供候选。**

素材顺序：5 秒成稿 → 10 秒拖气泡 → 10 秒圈手部与对比 → 5 秒独立 API 配置 → 安装/体验链接。提供完整来源与限制，避免只展示最好的生成结果而隐藏回填步骤。

不要购买 Star、互刷、发奖励换 Star、批量私信，或把“没 Key 可启动网站”宣传成“免费无限 AI 出图”。更广泛的泛流量不一定是目标使用者。可在用户已看过作品和体验后放一句自愿 Star 邀请，不弹窗、不阻断下载。

可直接改写使用的文案见 [LAUNCH_COPY](LAUNCH_COPY.md)。发布前替换具体版本、已验证服务和实际演示链接；这些文件是草稿，不会自动发往其他平台。
