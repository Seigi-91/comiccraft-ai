# 可核查的漫画创作知识库 · v2

六个角色各4张，共24张原创知识卡。每张卡包含**适用条件、项目规则、正例、反例、解释、限制、检查项和检索别名**。16张卡有可定位的教学、实践或原始研究来源，2张有同类项目的工程参考，另6张是项目自定规则。每条证据标明它具体支持的主张。

## 六个角色

| 角色 | 覆盖主题 |
|---|---|
| 剧情策划 | 因果、人物动机、短篇节拍、时间线 |
| 分镜 | 叙事节拍、景别/机位、轴线/视线、动作匹配、主格与嵌入格。子镜头选择覆盖细节、主观视点、反应、动作推进、短回忆和并行行动 |
| 台词 | 人物声音、说明与沉默、可排字脚本、指代连续 |
| 画面 | 身份与服装、结构参考与当前状态、手姿接触、光色连续 |
| 审核 | 可见证据、严重度、修复范围、基准与读者反馈 |
| 排版 | 画内气泡、说话人分隔、文字容量、尾尖与阅读路径 |

## 实际运行机制

- 分镜基础卡提供六类子镜头的选择条件。专项卡把主观视点、动作推进和时空切换分别纳入角色检索。新的因果节拍单独分格，短回忆或并行行动可在有清楚提示时作为当前节拍的补充。[分镜卡与示例](CARD_CATALOG.md#board-intent--导演式分镜每格的叙事任务)
- 数据在 `cards.json`。启动/读取时校验来源存在、正文核对状态、证据定位、知识性质和正反例等结构；受限来源不能充当支持证据。
- 检索先按角色硬筛选，必带一张基础卡，再用中文双字词/英文词、标签和中英别名作加权词汇排序，最多加入两张专项卡。无匹配时只保留基础卡，不补无关条目。这不是向量检索或模型微调。
- 提示词分别标出来源支持的主张和本项目规则，并加入适用条件、正反例与限制。当前查询不是原始来源中的结论，不会提升成机构背书。
- 生成任务开始时冻结完整知识语料；同一个任务恢复仍用冻结版本。显式新建的任务捕获当前版本。旧任务没有快照时首次恢复只能记录当时的知识，不能还原不存在的历史。
- 任务记录保存卡片/证据编号、SHA-256、命中词、阶段和任务编号。卡片哈希包含来源元数据。升级角色代码/输出Schema仍须检查兼容性；知识快照不是完整运行环境快照。
- 设置页可查看全文、具体证据、正反例、限制和命中词，并创建有/无知识的ChatGPT对照任务。实验包冻结完整提示词及其差异；不自动调用模型API。

## 研究与效果是两件事

检索检查证明“能否找到预期条目”，流程测试证明“能否把条目交给模型”，都不能证明漫画画质或故事质量提升。知识对照实验可独立录入两组结果。正式创作使用已配置的自动连接。实验效果以实际输出与评分为依据。

对照实验目前比较**文字创作建议**，不生成图片、不冒充完整漫画实验。需要图像级结论时应按固定六格案例另行生成、保留全部候选并做图像评审。

## 修改、许可与复核

维护者可编辑JSON并运行 `python -m scripts.evaluate_knowledge --output benchmarks/knowledge-retrieval-report.json` 和测试。新增来源先核对指定章节；新增卡须提供应用边界与反例，不能只放机构主页。知识更新不会改写任务快照和已评审实验。

正文、原创案例和项目规则采用MIT。外部来源只提供链接和有限原创归纳，不打包教材、影片、图例或字体，亦不代表这些机构认可本项目。检索检查题由维护者编写，外部专家复核、独立数据集和真实效果评审仍是后续工作。
