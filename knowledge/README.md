# 六个 Agent 的专业知识库

本轮加入 **24 张项目原创知识卡，每个角色 4 张**。这些是为漫画任务编写的应用笔记和检查表，不是教材全文、导演授权教程或某位导演风格的仿写。卡片正文按本项目 MIT 分发；外部链接保留原权利，未打包网页、图例、书籍和字体。

| Agent | 知识主题 |
|---|---|
| 剧情策划 | 因果结构、人物欲望与需要、短篇节拍、事实与时间线 |
| 分镜 | 每格叙事任务、景别/机位、180度轴线与正反打、动作/道具衔接、格间时间 |
| 台词 | 人物声音、潜台词、沉默、可排版短句、称谓与知识边界 |
| 画面设计 | 身份与服装、空间层次、手部接触、光色和材质连续 |
| 视觉审核 | 附图证据、分项严重度、局部修复范围、基准与完整页检查 |
| 排版 | 阅读路径、脸/手/道具保护、容量与字号、尾尖、特效和输出验证 |

## 实际接入，而不只是放文件

1. 知识保存在 `knowledge/cards.json`，按角色硬筛选，避免分镜任务拿到无关排版知识。
2. 每次 agent 构造任务提示词时，必带该角色一张基础卡，再用任务文字的中文双字词/英文词及标签加权匹配选择两张相关卡。
3. 无匹配时使用该角色的后备卡，并标注 `role_fallback`；不是假称匹配到了相似案例。
4. 知识片段附卡片 id、SHA-256 与延伸阅读链接，进入 ChatGPT 待办或实际 API 提示词。剧情、分镜、台词、画面、审核均已调用；气泡视觉定位也读取排版知识。
5. 生成任务保存 `state.knowledge_evidence`：角色、卡片、哈希、选择原因及执行阶段。生产工作台的「一致性与证据」可查看。
6. 在「创作团队与设置」选择 agent，可展开全文与来源、按任务语句试检索。

**这是本地、可审阅的词汇检索增强，不是向量检索，不是训练或微调模型，也不是完整的长篇世界观 RAG。** 不要求额外数据库、嵌入服务或 Key。专业规则是决策参考，不能覆盖用户要求或输出 JSON Schema；确定性的边界和交叠仍由程序校验。

## 分镜知识举例

输入“两人对话，需要正反打并保持视线轴线”：分镜师会得到基础的“每格叙事任务”卡，加上相关的轴线与衔接卡。应用要求是先交代两人位置，再保持可读的视线关系；若跨轴，用建立镜头等方法重新说明空间。电影中的镜头运动要转换为漫画前后格变化，不要求单张静态图完成推拉摇移。

该方法采用通用影视叙事术语，不宣称某位导演亲自提供建议，也不把轴线惯例当作不可打破的禁令。

## 来源边界

- [Yale Film Analysis: Editing](https://filmanalysis.yale.edu/editing/) 与 [Cinematography](https://filmanalysis.yale.edu/cinematography/)：连续性与画面语言的延伸阅读。
- [Adobe: Storyboarding](https://www.adobe.com/creativecloud/video/discover/storyboarding.html)：从剧本到可执行分镜的参考。
- [Pixar in a Box](https://www.khanacademy.org/computing/pixar/storytelling)：官方课程入口；本次页面正文受访问限制，因此不标注逐条引文或假称完整阅读课程。
- [Nate Piekos / Blambot](https://blambot.com/pages/lettering-tips)：专业 lettering 图例入口；没有复制图例或字体，也不把美漫惯例直接当中文规则。
- [W3C Contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)：可读性参考；不宣称整个漫画或网站已获 WCAG 认证。

## 维护方法

编辑 `cards.json` 中的原创内容，保留唯一 id、role、tags、sources、core、reviewed_at。每个角色保留一张基础卡；新来源先加入 sources 表并核对可访问性和权利。文件修改时间变化后进程会重新读取，知识哈希随正文改变；旧生成记录不会改写。历史记录只保存卡片指纹和提示词，若需完整知识版本可通过对应 Git 提交还原。

不要把私人参考书扫描件直接提交到公开仓库。后续若扩展用户知识导入，需要项目隔离、资料权限、检索评测和引用溯源，不能仅把所有 PDF 拼进提示词。
